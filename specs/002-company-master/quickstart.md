# Quickstart: Company Master CRUD

This guide validates the Company Master after implementation. It does not change schema or application data.

## Prerequisites

- .NET 10 SDK and Node.js/npm for the existing projects.
- JDK 11 or later for OpenAPI Generator; the CLI version is pinned in `Spec-Driven-Development/sdd-ui/openapitools.json`.
- The API connection configured through `ConnectionStrings__BrokerConnection`. Do not print or commit its value.

## API-first contract workflow

The Angular client is generated from the API's OpenAPI output; neither the OpenAPI document nor generated client files are edited by hand.

1. Start the API in Development with its configured connection string:

   ```powershell
   dotnet run --project .\Spec-Driven-Development\SDD.API\SDD.API\SDD.API.csproj --urls http://localhost:5114
   ```

2. In another terminal, capture the document produced by the running API:

   ```powershell
   Invoke-WebRequest http://localhost:5114/openapi/v1.json -OutFile .\Spec-Driven-Development\SDD.API\SDD.API\openapi.json
   ```

   OpenAPI generation does not call company endpoints or modify database data.

3. Generate the typed Angular client:

   ```powershell
   npm --prefix .\Spec-Driven-Development\sdd-ui run generate-api-client
   ```

   Complete API implementation and client generation before implementing or changing Company Master UI contracts.

## Automated checks

From the repository root, run:

```powershell
.\scripts\test.ps1
```

Expected: API unit tests, Playwright tests with mocked API responses, and Angular Vitest pass; any failure returns a non-zero exit code. The script builds Release, installs Chromium when needed, and runs the test suites. Tests use code-side fakes or mocked API responses and do not connect to or change a database.

## Manual end-to-end checks

The automated Playwright suite is the supported CRUD validation because it mocks API responses. Do not create, edit, or delete records against a configured database during testing.

Start the API and UI in separate terminals:

```powershell
dotnet run --project .\Spec-Driven-Development\SDD.API\SDD.API\SDD.API.csproj
```

```powershell
npm --prefix .\Spec-Driven-Development\sdd-ui start
```

In Company Master (use mocked API responses for UI checks; do not write test records to a database):

1. Confirm the list shows the specified columns, pagination, sorting, and a filter for each data column; the action column has a keyboard-accessible history tooltip.
2. Set a page, sort, and filters, open a company, then return; verify list state is restored.
3. Verify history is available on focus and hover.
4. Verify create/edit fields, required and length validation, duplicate-code feedback, short-name prefill/editing, and date-picker selection/typing using mocked API responses.
5. Open company details, edit mutable fields, and verify company code and name cannot be changed.
6. Verify last-write-wins behavior with code-only service tests using a fake data source.
7. Verify delete confirmation, cancellation, success, and reference-conflict feedback using mocked API responses.
8. Verify validation errors are highlighted at their fields and the first invalid field is focused and scrolled into view; verify server failures do not show success.

Do not connect tests to the database or use real company records for CRUD validation. Review [the data model](./data-model.md) for field limits and verify request/response shapes from the OpenAPI document generated by the API.
